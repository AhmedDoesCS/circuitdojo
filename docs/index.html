CircuitDojoThe Manual

Beginner → industry level

Build software
like this yourself.

This manual takes someone who can program a little, but has never touched JavaScript, React, a database or a design system, and walks them all the way to being able to build an application of this complexity on their own, from an empty folder.

What you will be able to do

By the end you should be able to sit down with an empty folder and:

  • Set up a modern front-end project from scratch and understand every file in it.
  • Write JavaScript fluently: closures, modules, immutability, async, and know why each idiom exists.
  • Build a React application with real state: undo/redo, keyboard control, canvas interaction.
  • Design a data model, write the SQL, and secure it so a browser can talk to the database directly.
  • Make it look like someone with taste built it, and explain every decision you made.
  • Test it, debug it, and ship it to the public internet.
How to read this

Straight through, in order, with the project open in an editor beside you. Every concept is introduced with the smallest possible example, then shown again as it actually appears in CircuitDojo, because seeing a hook in a 5-line demo teaches you the syntax, and seeing it in a 400-line canvas component teaches you the judgement.

The chapters

Chapter 01

Foundations

How the web works, what a browser really does, HTML and CSS in one sitting, and the tools on your machine: terminal, Node, npm, git.

 Chapter 02

JavaScript

The whole language you need: values, functions, closures, objects, arrays, destructuring, modules, classes, async, errors, immutability.

 Chapter 03

React

Rendering as a function of state. JSX, props, hooks in depth, reducers, refs, context, performance, and the anti-patterns to avoid.

 Chapter 04

Tooling

Vite, npm scripts, bundling, environment variables, DevTools debugging, automated tests, git workflow, undoing a change you regret, and deployment.

 Chapter 05

Backend & data

Client/server basics, REST, relational modelling, SQL you will actually write, auth, and row-level security with Supabase.

 Chapter 06

Design

Type scales, spacing rhythm, colour discipline, glass and depth, motion with intent, game-menu layout, accessibility. The "awwwards feel", decomposed into rules you can apply.

 Chapter 07

Architecture

How this app is actually built: the engine/UI split, union-find netlists, a declarative rules DSL, and state machines for overlays.

 Chapter 08

Recipes

Copy-paste patterns with the reasoning attached: glass surfaces, undo stacks, keyboard maps, seeded randomness, canvas pan/zoom, RLS policies.

Manual changelog

This manual is kept in step with the application. Every time the app gains a technology, a pattern or a design decision, the relevant chapter is updated and the change is listed here.

Revision 5 - progress, drawn as a circuit

  • New: chapter 06 gains "Designing progress: a checklist looks backwards", on why a complete and correct list of what you have learned is inert, and on building a metaphor out of the nouns the product already draws.
  • New: the same section covers separating selection from commitment, which is what turns a locked row from a dead end into the reason the screen exists.
  • New: chapter 07's placement section gains "Where this model quietly stopped being true": what happens to every claim in a product when you replace the system that used to read them, and why an orphaned claim is worse than a broken one.
  • New: chapter 06 gains "Identity: the email address is not a name", on what a one-line fallback decides about a product's tone, on building customisation out of components you already own instead of accepting uploads, and on solving a twelve-colour palette rather than picking one.

Revision 4 - the curriculum, and the numbers inside it

  • New: chapter 07 gains "Content that proves itself", on grading authored content against the thing that will grade the learner.
  • New: chapter 06 gains "Two numbers that disagree", on what happens when a headline figure is derived from a model the product no longer runs on.
  • Updated: chapter 02's formatting section now covers why one number formatter is not enough: engineering notation for values, ordinary decimals for prose.

Revision 3 - every challenge gets a drawn answer

  • New: chapter 07 gains "What the remaining twenty-four found": the three engine faults and two impossible challenges that only a complete correct circuit could expose.
  • New: chapter 07 gains "A reference drawing is held to a stricter standard than a correct one", and the test that enforces it.
  • New: chapter 06 gains "The panel has to know which way the drawing runs": how a layout quietly degrades when its content changes shape, and which dimension is actually scarce.
  • Updated: chapter 07's edge-kind table gains clamp, the kind that exists so a TVS is not mistaken for a short.

  • New: chapter 08 gains recipes for a full-screen menu shell, a re-entrant transition, and provisional-state modelling (the level placement system).

Reading order if you are in a hurry

"I want to build a UI this week"

01 → 02 (skim the async section) → 03 → 06. Come back for 05 when you need to save data.

"I want to understand this codebase"

07 first, then 03 for the UI layer and 02 for any syntax that stops you.

"I want my work to look designed"

06 end to end, then 08's design recipes. Chapter 06 assumes no design background.

"I want to ship something real"

04 → 05, then the deployment section at the end of 04.

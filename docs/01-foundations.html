Chapter 01

Foundations

Before any framework: what a browser actually does when it loads a page, the three languages it speaks, and the four tools on your machine that every professional project depends on.

The mental model: three languages, one runtime

A web application is a program that runs inside a browser. The browser gives you exactly three languages, and each has one job:

LanguageJobAnalogy
HTMLStructure and contentThe skeleton
CSSAppearance and layoutThe skin and clothes
JavaScriptBehaviour over timeThe nervous system

Everything else: React, Tailwind, Vite: is a tool that eventually produces those three things. Nothing you learn later replaces this layer; frameworks only make it easier to generate.

What happens when you open a page

  1. The browser asks a server for a URL over HTTP and gets back HTML text.
  2. It parses that HTML into the DOM: a tree of objects, one per element.
  3. It finds <link> and <script> tags and fetches those files too.
  4. It applies CSS to the tree, works out geometry (layout), then paints pixels.
  5. It runs your JavaScript, which can change the DOM, and any change can trigger layout and paint again.
Why this matters

"Layout then paint" is why some CSS properties are cheap to animate and others are expensive. transform and opacity can be handled by the compositor without re-running layout; animating width or top forces layout on every frame. Chapter 06 leans on this constantly.

HTML in one sitting

HTML is a tree of elements. An element is a tag, optional attributes, and children.

<article class="card" id="intro">
  <h2>A heading</h2>
  <p>Some text with <strong>emphasis</strong>.</p>
  <button type="button">Do the thing</button>
</article>

The whole of CircuitDojo's HTML is this, twelve lines:

<!doctype html>
<html lang="en">
  <head>
    <meta charset="UTF-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1.0" />
    <title>CircuitDojo</title>
  </head>
  <body>
    <div id="root"></div>
    <script type="module" src="/src/main.jsx"></script>
  </body>
</html>
Why so little

This is a single-page application. The server sends one nearly-empty page; JavaScript builds the entire interface into #root at runtime. The trade: much richer interaction, at the cost of needing JavaScript to run at all. For a schematic editor that is obviously the right trade. For a blog it would be the wrong one.

Attributes worth knowing immediately:

  • id: unique name, used by JS and by #anchor links.
  • class: a label you can style or select many elements with. Tailwind uses these heavily.
  • data-*: your own metadata. CircuitDojo uses data-prop-field="value" so a keyboard shortcut can find and focus the right input.
  • aria-* and role, accessibility information for screen readers.

CSS in one sitting

A CSS rule is a selector plus declarations.

.card {              /* every element with class="card" */
  padding: 1rem;
  border-radius: 18px;
  background: rgba(255, 255, 255, 0.78);
}

The box model

Every element is a box: content, then padding, then border, then margin.

/* Set this once, globally, and stop fighting sizes forever. */
* { box-sizing: border-box; }
Why

With border-box, width: 300px means the box is 300px including padding and border. Without it, padding is added on top and every layout becomes arithmetic. Both this manual and Tailwind's reset set it.

Layout: flex and grid

Two systems. Learn both; you will use them daily.

/* Flexbox: one dimension. "Put these in a row, spaced out." */
.toolbar { display: flex; align-items: center; gap: 0.5rem; }

/* Grid: two dimensions. "Sidebar of 280px, then everything else." */
.layout { display: grid; grid-template-columns: 280px minmax(0, 1fr); }

minmax(0, 1fr) is the single most useful incantation in CSS grid: "take the remaining space, but you are allowed to be narrower than your content". Without the 0, a long line of code inside the column makes the whole page scroll sideways. CircuitDojo's layouts use it everywhere.

Positioning and stacking

ValueBehaviourUsed in this app for
staticNormal flow (default)Most content
relativeNormal flow, but offsettable and a positioning parentGlass cards with a gloss layer
absoluteRemoved from flow, positioned inside nearest positioned ancestorFloating widgets over the canvas
fixedPositioned relative to the viewportFull-screen overlays, the iris wipe
stickyNormal until it hits an offset, then fixedThis manual's sidebar

z-index decides who covers whom, but only among positioned elements. CircuitDojo keeps a written ladder so overlays never fight: widgets z-20, modals z-50, brief z-60, celebration z-70, iris wipe z-120.

Trap

A parent with overflow: hidden clips absolutely-positioned children, and a parent with a transform becomes the containing block for position: fixed descendants. Most "why is my modal cut off?" bugs are one of those two.

Custom properties (CSS variables)

:root { --zinc-900: #18181b; --s4: 1rem; }
.card { color: var(--zinc-900); padding: var(--s4); }

Variables cascade like any other property, which makes them perfect for design tokens: one definition, used everywhere, overridable per-section.

Learned the hard way, in this project

A CSS variable inside an animatable property does not interpolate reliably. clip-path: circle(var(--iris)) plus a transition produced a wipe that jumped straight to its end state. The fix was to use @keyframes with literal values. Chapter 06 tells the whole story.

The four tools on your machine

1 · The terminal

A prompt where you type commands. You need about eight:

pwd                 # where am I
ls                  # what is here
cd my-project       # go into a folder
cd ..               # go up one
mkdir new-folder    # make a folder
code .              # open this folder in VS Code
npm install         # install dependencies
npm run dev         # start the dev server

On Windows, PowerShell is the default. It is not the same shell as macOS/Linux: && does not chain commands in older versions, and it has its own cmdlet names. If a tutorial's commands fail, that difference is usually why.

2 · Node.js

JavaScript, running outside a browser. It is what lets JS be used for tooling: your bundler, your test runner and your scripts are all Node programs. 

node --version      # v22.x
node script.mjs     # run a file
node --test tests/  # run the built-in test runner

3 · npm

Node's package manager, and the script runner every project uses as its front door.

{
  "scripts": {
    "dev": "vite",
    "build": "vite build",
    "test": "node --test tests/*.test.js"
  },
  "dependencies":    { "react": "^18.3.1" },   // ships to the browser
  "devDependencies": { "vite": "^5.4.8" }     // build-time only
}
FileWhat it isCommit it?
package.jsonYour declared dependencies and scriptsYes
package-lock.jsonThe exact resolved versions, so installs are reproducibleYes
node_modules/The downloaded code itself: huge, regenerableNo

^18.3.1 means "18.3.1 or any later 18.x". The caret is why a lock file exists: without it, two people installing on different days can get different code.

4 · git

Version control. The five commands that cover 95% of solo work:

git init                         # start tracking this folder
git status                       # what changed
git add -A                       # stage everything
git commit -m "Add iris wipe"   # save a checkpoint
git log --oneline                # history

Commit in small, meaningful units, and write the message as "what this changes and why". Your future self reading git log during a bug hunt is the audience.

A .gitignore keeps generated and secret files out of history:

node_modules
dist
.env
Never commit

.env files, API secrets, or anything with the word "service role" in it. Once a secret is in git history it is effectively public: rotating the key is the only real fix.

Anatomy of this project

CircuitDojo/
├─ index.html            # the single page
├─ package.json          # dependencies + scripts
├─ vite.config.js        # dev server + build config
├─ tailwind.config.js    # design tokens
├─ postcss.config.js     # CSS pipeline
├─ src/
│  ├─ main.jsx           # entry point: mount React into #root
│  ├─ App.jsx            # top-level component, owns the view state
│  ├─ index.css          # Tailwind + component classes
│  ├─ components/        # UI
│  ├─ state/             # hooks that own state
│  ├─ engine/            # pure logic, no React
│  ├─ schematic/         # domain model
│  ├─ challenges/        # content + generation
│  └─ lib/               # small shared utilities
├─ supabase/migrations/  # SQL
├─ tests/                # node:test suites
└─ docs/                 # this manual

The entry point is four lines of real work:

import React from 'react';
import { createRoot } from 'react-dom/client';
import App from './App.jsx';
import './index.css';

createRoot(document.getElementById('root')).render(
  <React.StrictMode><App /></React.StrictMode>
);
Why folders by role, not by feature

engine/ contains no React and no DOM; components/ contains no electrical rules. That boundary is the single most valuable structural decision in the project: it means the entire grading engine can be tested in Node in milliseconds, with no browser and no mocking. Chapter 07 develops this idea properly.
